# Протокол совместной работы AI — Sonata Optics
Обновлён по поручению владельца 15.11.2026. Текущая цель — рекламная стратегия для Словакии. Расширение на другие страны — после проверки словацкой модели.

## 1. Участники и ответственность

С третьего круга в обязательном обсуждении участвуют три модели: ChatGPT, Gemini и Claude Cowork. Grok — дополнительный рецензент по отдельному поручению; его прошлые отзывы сохраняются. Claude Cowork и Claude Code — разные роли, их нельзя считать одним голосом.

| Участник | Ответственность |
| --- | --- |
| ChatGPT | Модератор и общий стратег. Собирает фактуру, анализирует Google и Meta, формулирует предложения, ведёт реестр замечаний, подводит итоги и передаёт задачи. Его собственные выводы также подлежат критике. |
| Grok | Проверяет слабые предпосылки, коммерческие риски, конкурентов, альтернативы и ограничения. Для правовых и платформенных утверждений нужны источники. |
| Gemini | Особое внимание Google Ads, Merchant, семантике, фидам, измерению и взаимосвязи каналов. |
| Claude Cowork | Особое внимание экономике, качеству данных, атрибуции, воронке, реализуемости и независимой проверке расчётов. |
| Claude Code | Финальный исполнитель: техническое задание, код, вёрстка, подготовка фидов, трекинга и других согласованных материалов. Не пятый участник стратегического голосования. |

**Каждый из трёх обязательных участников рецензирует всю стратегию**, включая Google, Meta, ассортимент, экономику, измерение, креативы, посадочные страницы и риски. Специализация не ограничивает право и обязанность критиковать другие части.

## 2. Строгая последовательность

С третьего круга порядок по решению владельца:
1. **ChatGPT** публикует фактуру, предложение и вопросы.
2. **Gemini** проверяет архитектуру и всю стратегию; передаёт Claude Cowork.
3. **Claude Cowork** независимо проверяет данные, экономику и реализацию; передаёт ChatGPT.
4. **ChatGPT** отвечает на замечания и публикует итог. Grok не является обязательным этапом.

Модератор после прочтения ответа сам сохраняет критику, обновляет STATUS/ISSUES и публикует конкретное задание следующему участнику. Не заканчивать только обещанием передачи и не ждать повторного поручения на оформление.

Модели не утверждают, что общались между собой, если этого не было. Пользователь переносит ответы из Grok/Gemini/Cowork сюда; ChatGPT сохраняет их в GitHub с указанием авторства и передаёт готовое задание следующему участнику. При наличии прямой записи участник может сохранить ответ сам и передать ссылку. Пропущенный ответ не считается согласием. Ответ, пересказанный пользователем, помечается как пересказ.

## 3. Два обязательных круга и третий при необходимости

**Круг 1 — предложение и полная критика.** Проверяем фактуру, состав ассортимента, допуск каналов, измерение, экономику и варианты стратегии. Результат: версия v1 и список открытых замечаний.

**Круг 2 — повторная проверка и исправления.** Все обязательные участники проверяют обновлённую стратегию целиком, ответы на замечания первого круга и новые риски. Каждое прежнее замечание получает статус. Результат: версия v2, условия запуска и оставшиеся разногласия.

**Круг 3 обязателен**, если остались критические противоречия, не подтверждены необходимые для запуска ограничения, существенно изменены бюджет/каналы/измерение либо кто-то обоснованно оспаривает закрытие блокирующего замечания. Повторяется тот же порядок; акцент на открытых вопросах и последствиях изменений.

После третьего круга нельзя объявлять консенсус искусственно. Нерешённые вопросы фиксируются с вариантами, доказательствами и рекомендацией для владельца. Опасную или неподтверждённую часть исключают из реализации до решения; готовые независимые части можно включить в итог.

Стратегия готова к передаче, когда завершены минимум два круга, все обязательные участники дали ответы, нет открытых блокирующих замечаний по передаваемому объёму, определены метрики, бюджетные допущения, критерии остановки и проверки результата. Молчание и большинство голосов не заменяют доказательства.

## 4. Обязательная критика и доказательства

- В каждом ответе обязателен раздел «Критика и риски»: минимум две содержательные проверки слабых мест. Для каждого — конкретный тезис, риск, доказательство или недостающие данные, исправление и способ проверки.
- Не выдумывать дефекты ради количества. Если дефект не найден, описать проверенную гипотезу риска, способ проверки и остаточную неопределённость.
- Критиковать аргументы всех предыдущих участников, а не только последнего. Во втором/третьем круге каждый также пересматривает свои прежние выводы.
- Помечать утверждения: **ФАКТ / ГИПОТЕЗА / НЕТ ДАННЫХ**. Для факта — файл/раздел/дата или первичный источник. Если файл недоступен, прямо указать это.
- CPC, CPM, CR, CPA, ROAS и маржа: источник и период либо явно обозначенный сценарий. Не выдавать прогноз за измерение, не придумывать норматив для Словакии.
- Уточнять определения конверсий, атрибуцию и период. Conversions и Conversion value не равны автоматически покупкам и выручке.
- Для каждого существенного замечания использовать постоянный ID: R1-GROK-01, R1-GEMINI-01, R1-COWORK-01, R1-CHATGPT-01 и т. д. При повторном обсуждении сохранять ID.
- Критичность: **блокирующее / существенное / улучшение**. Статус: **открыто / принято в работу / исправлено, ждёт проверки / закрыто / отклонено с обоснованием / решение владельца**.

## 5. Единый шаблон ответа

Использовать [шаблон](discussions/template_review.md). Обязательная структура:

1. Автор, круг, дата, версия стратегии и SHA коммита, реально прочитанные файлы.
2. Резюме: до 10 строк — главный вывод, главное изменение, главный риск.
3. Что поддерживается и на каких основаниях.
4. Критика и риски с ID и проверками.
5. Ответ на предыдущие замечания и позиции каждого участника.
6. Конкретное контрпредложение: действие, ожидаемый эффект, допущения, метрика и критерий остановки.
7. Что требует фактов или решения владельца.
8. Передача следующему: имя участника, входные ссылки, 3–5 точных задач и ожидаемый результат.

Нельзя заканчивать общим «пусть следующий посмотрит». Передача должна быть готовым заданием.

## 6. Резюме модератора и хранение

Ответы сохраняются отдельно в discussions/round-01/, round-02/, round-03/:
Круги 1–2 сохраняют исторические имена. С круга 3: 01_chatgpt_proposal.md (если есть) → 02_gemini_review.md → 03_chatgpt_handoff_to_claude.md → 04_claude_review.md → 05_chatgpt_summary.md.

Сохранять оригинал ответа, не переписывать чужую позицию задним числом. Исправления — отдельным дополнением с датой. ChatGPT ведёт:
- [Текущий статус и следующее задание](discussions/STATUS.md).
- [Реестр замечаний](discussions/ISSUES.md).
- В итогах каждого круга: принято, отклонено с причиной, открыто; таблица ID/автор/статус/изменённый файл/доказательство/кто проверяет; различия с прошлой версией; точная следующая задача.

Итог стратегии фиксируется отдельным коммитом. Финальное ТЗ для Claude Code должно ссылаться на этот SHA, согласованные решения, исключения, критерии приёмки, зависимости и порядок проверки. Указывать, какие решения уже разрешены владельцем, а какие остаются открытыми.

## 7. Передача Claude Code

После обсуждения ChatGPT собирает реализационное ТЗ. Claude Code проверяет техническую выполнимость, реализует согласованный объём, показывает результат и отчёт: изменённые файлы, проверки, ограничения. Новое противоречие возвращается модератору, а не решается скрытой сменой стратегии.

ChatGPT проверяет соответствие стратегии, Claude Cowork — измерение и расчёты там, где они затронуты. Вёрстка и подготовка материалов не означают автоматический запуск рекламы: расход бюджета и изменения живых кампаний должны соответствовать явному разрешению владельца.

## 8. Ассортимент и границы данных

Прицелы — основной ассортимент бизнеса. Их отсутствие в Google-фиде — сознательное ограничение канала, а не снижение коммерческого приоритета. Учитывать полный каталог сайта.

Допуск проверяется отдельно для Google Ads, Merchant, Meta Ads, органических публикаций и Meta Commerce. Включение прицелов в Meta-стратегию не подтверждает разрешение платных объявлений. Не возвращать исключённые прицелы в Google и не обходить правила переименованием или маскировкой.

Репозиторий публичный. Полные финансовые выгрузки и приватные данные находятся отдельно; отсутствие доступа явно фиксируется. Публиковать секреты, персональные данные или закрытые выгрузки без соответствующего разрешения нельзя.
