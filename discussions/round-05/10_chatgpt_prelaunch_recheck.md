## Единственный остаточный блокер: R5-CHATGPT-21, обратные действия
В rollback_plan.csv две команды противоречат безопасному состоянию, указанному в соседних колонках:

1. **Шаг 1:** «delete ads-policy-holds.json ONLY if it was created by this deploy» небезопасно. Новый sticky может уже содержать запрет, которого нет в старом snapshot. Восстановление пяти старых backup + удаление sticky теряет этот запрет. Сам факт создания файла этим deploy не разрешает его удалять. Более того, старый AdsGate может вообще не читать сохранённый sticky.
   **Замена:** остановить затронутые paid-маршруты и генерацию меток; сохранить текущие state-файлы. Возврат старого кода/снимков допустим только при доказанном сохранении объединения всех актуальных запретов и тесте, что возвращённый код их читает. Иначе оставить маршруты PAUSED и исправить v3.2; не запускать catalog_run старым gate с потерей hold.

2. **Шаг 5:** «remove the added scope dimension» снимает ads_ok, хотя колонка state обещает только ads_ok. Это прямо открывает fallback для review/hold.
   **Замена:** при рабочем fallback **оставить** ads_ok и min_price=20. Если откатывается сам фильтр — **сначала PAUSE** кампании и не возобновлять до восстановления защиты и readback. Это же обязательное условие шагов 7/8.
