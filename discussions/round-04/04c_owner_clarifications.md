## Техническая категория bresser.de / «BrsFDE»
Владелец подтвердил: это историческая техническая категория с неразобранными товарами. Задача распределить товары по нормальным категориям уже выполняется; после переноса техническую категорию удалят. Завершение миграции не подтверждено.
Не проектировать постоянную кампанию/сегмент по этой категории. После миграции сверить по стабильному product_id/offer_id: старую и новую категорию, роль, наличие, допуск и проектный маршрут. Удаление категории не означает удаление самих товаров. Проверить, что товары не потерялись и новые категории дошли до фида/меток/проектных фильтров. До подтверждения использовать проверенный реестр ID; не предполагать автоматического обновления label0. Исправление monokulár/okulár остаётся нужным для классификатора, но не строить отдельную постоянную систему bresser.de. Точное техническое имя/ID удаляемой категории сверить с выгрузкой; запись «BrsFDE» — слова владельца.

## OWNER_DECISION: направление, не пакетное удаление
Владелец сомневается в необходимости отсекать «где купить», «подобрать», «недорого», «описание»: эти слова может использовать покупатель.
Решение модератора для проекта: не исключать релевантный запрос продаваемой модели только из-за таких слов. Code должен представить построчный proposed diff с учётом match type и уровня минуса; общее снятие всех минусов аккаунта не разрешено. Это не закрывает автоматически все 15 OWNER_DECISION и 7 OWNER_DECISION_CATALOG; stary/старое поколение и каталожные неоднозначности требуют отдельных примеров.
Heureka: окончательного решения нет. Владелец отметил навигационный характер, затем допустил полезность собственного показа. Сохранить OWNER_DECISION_HEUREKA, отдельно разобрать чисто навигационные запросы и «конкретная продаваемая модель + Heureka». Подготовить варианты с контролем расходов для последующей Google-рецензии; тест и расходы сейчас не разрешены.
