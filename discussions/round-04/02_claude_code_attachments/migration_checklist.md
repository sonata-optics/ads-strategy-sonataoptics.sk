## 1. Проект пилота (ПРЕДЛОЖЕНИЕ)
| Параметр | Значение | Комментарий |
| --- | --- | --- |
| Кампания | `SK_SHOP_Models_Pilot`, Standard Shopping, создать **PAUSED** | Новая кампания не наследует campaign negatives старых, наследует account list |
| Приоритет | `campaign_priority = 1` (Medium) при текущем 0 у всех | Выше старых: при пересечении ставку делает пилот. Показов не гарантирует |
| Feed / страна | Merchant 5831333799, feed_label `SK`, язык `sk`, канал ONLINE | Совпадает с identity из `shopping_product.resource_name` |
| Состав | Строгий allowlist из **26 item_id** (22 IN_STOCK + 4 OOS) | Отклонение от Cowork r3 (22 SKU): OOS включены, чтобы при возврате наличия им не требовалось включение синхронизацией |
| Дерево | В каждой группе `item_id = X` INCLUDED; **everything else EXCLUDED** на каждом уровне | Ни один другой товар не может попасть в пилот |
| Группы | Одна ad group на item_id (`SHOP_<FAMILY>_<id>`) | Ставка по SKU; отчёт product × ad group |
| Минус-слова кампании | bazár, bazar, použitý, pouzity (BROAD) + návod/manuál/pdf/servis/oprava (PHRASE) | См. diff; не копировать широкие «ďalekohľad/cena» |
| Бюджет, ставки, расписание, гео | **Согласуемые параметры, не заданы** | Не выдумываются; экономика — сценарии Cowork |
| Старые кампании | **Не меняются** | Хвост каталога остаётся в действующих кампаниях |

Почему не менять одновременно старые scopes и пилот: при одновременном изменении нельзя отделить эффект приоритета от эффекта исключения, и откат одного шага ломает другой. Исключение из старых кампаний — отдельный будущий шаг (раздел 5) с отдельным обоснованием.

## 2. Статические проверки до включения (без показа рекламы)
1. Снимок T0: JSON всех listing groups, campaign/ad group negatives, бюджетов и end dates 8 Shopping-кампаний; SHA-256 файла в журнале.
2. Пилот PAUSED создан → `shopping_product WHERE campaign = pilot` возвращает **ровно 26** item_id из allowlist; ни одного лишнего.
3. Для 22 IN_STOCK — статус в пилоте ELIGIBLE (или задокументированная причина, кроме `in_any_campaign`); для 4 OOS — `not_eligible_out_of_stock` (это PASS).
4. 26130 в пилоте: причина `not_eligible_in_any_campaign` исчезла. Label не менялся (`monokuláre`).
5. Старые кампании: та же выборка, что в T0 (24 ID в двух scoped-кампаниях, 26130/26131 нигде) — пилот их не изменил.
6. Каждая группа содержит одно INCLUDED-листо и EXCLUDED «everything else» (обход дерева через `ad_group_criterion`).
7. Приоритет пилота = 1, бюджет/ставки = утверждённые владельцем значения; гео/расписание соответствуют решению.
8. Минус-слова: прогон `routing_tests.py` с фактическими негативами пилота; R07–R09 зависят от решения по account `kde`.
9. Ad Preview (E11) **не подтверждает** доставку непрерывно запущенного пилота. Допустимо только как ручной снимок с указанием даты, устройства и гео; отсутствие в Preview не равно отсутствию права на показ.

Если любой пункт 2–7 не выполнен — не включать.

## 5. Исключение пилотных SKU из старых кампаний — отдельный шаг, не по таймеру
Нет автоматического исключения через 48–72 часа. Условия для отдельного решения:
1. Минимум N дней (значение согласуют Cowork/владелец) доставка пилота подтверждена отчётом показов по каждому IN_STOCK item_id или задокументирована причина нуля.
2. Бюджет пилота не ограничивал показы (иначе исключение из старых кампаний убирает fallback).
3. Повторный снимок T0′; исключение по item_id только в `24440851881` / `24451885423`, остальное дерево без изменений; diff деревьев проверен.
4. Откат — восстановление дерева из снимка.
