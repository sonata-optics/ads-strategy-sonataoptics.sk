# Синхронизация наличия → Search-группы: спецификация
Claude Code, круг 4, 15.11.2026. Закрывает проектную часть R3-CLAUDE-06 / R3-CHATGPT-10. **Не внедрено и не подключено к API.** Поведение проверено локальной моделью [stock_sync_dryrun.py](stock_sync_dryrun.py): 16/16 сценариев, журнал — [stock_sync_dryrun_log.csv](stock_sync_dryrun_log.csv), итоги — [stock_sync_dryrun_results.csv](stock_sync_dryrun_results.csv).

## 1. Что синхронизация делает и чего не делает
- Управляет **только** модельными Search-группами из allowlist (сейчас 4: AG_103933, AG_26113, AG_103640, AG_47420).
- **Не трогает Shopping.** OOS-товар в Merchant сам становится NOT_ELIGIBLE (подтверждено: 47424/47412/47458). Фид передаёт наличие правдиво; товар не удаляется из фида только из-за OOS.
- Не меняет бюджеты, ставки, ключи, объявления, фид.
- Не использует отсутствие показов как признак OOS. Единственный источник наличия — поле availability Merchant (или CS-Cart, если владелец выберет его основным, — тогда та же логика).

## 2. Идентичность товара
Составной ключ `merchant_id ~ channel ~ content_language ~ feed_label ~ offer_id`, например `5831333799~ONLINE~sk~SK~103933` (формат `shopping_product.resource_name`, подтверждён 15.11). `offer_id` один — не ключ: тот же ID в AT/CZ-фиде не должен влиять на SK-группу. Объект вне разрешённой identity пропускается (сценарий S10).

## 3. Состояние управляемого объекта
| Поле | Значения |
| --- | --- |
| status | ENABLED / PAUSED (фактическое из Ads на момент запуска) |
| pause_owner | `null` / `SYNC` / `MANUAL` / `REVIEW` |
| label | `paused-by-sync` ставится только синхронизацией и только при её паузе |
| in_stock_streak | число подряд свежих чтений IN_STOCK (хранится в журнале, переживает перезапуск) |
| allowlisted | true только для явно перечисленных групп |

`pause_owner` определяется по change history: последняя смена статуса не синхронизацией → MANUAL. Новая группа, созданная PAUSED для ревью, получает `REVIEW` и **никогда** не помечается `paused-by-sync` и не включается автоматически (S07).

## 4. Правила решения
| Вход | Действие |
| --- | --- |
| kill switch ON | ничего (S05) |
| ошибка API / таймаут | ничего, alert (S02) |
| пустой ответ | ничего, alert: пустой ответ ≠ всё OOS (S03) |
| чтение старше 6 ч (параметр) | ничего, alert (S04) |
| товар отсутствует в ответе | alert, без действия (S09) |
| OUT_OF_STOCK, группа ENABLED | PAUSE + label `paused-by-sync` (S01) |
| OUT_OF_STOCK, группа PAUSED | ничего |
| IN_STOCK, PAUSED, owner SYNC | ENABLE только после 2 подряд свежих IN_STOCK (S08, S16) |
| IN_STOCK, PAUSED, owner MANUAL/REVIEW | ничего, никогда (S06, S07) |
| IN_STOCK, ENABLED, но висит label | только снять label (человек включил вручную) (S13) |
| PREORDER / BACKORDER | без автоматического включения, нужно правило владельца (S14) |
| вне allowlist | ничего (S11) |
| за запуск меняется > 30 % allowlist и ≥ 2 объектов | HALT, ручное подтверждение (S12) |

## 5. Идемпотентность, журнал, dry-run
- Повтор с тем же входом не даёт действий (S15). Ключ действия: (object_id, target_status, hash чтения).
- Журнал на каждое решение: run_id, время, объект, identity, решение, причина, действие, hash входа; хранить ≥ 90 дней.
- Режимы: `dry_run` (по умолчанию, только журнал) → `apply` только после ревью журнала владельцем. Первые 2 недели — только dry_run.
- Аварийное отключение: флаг kill switch в конфиге проверяется первым; отключение не откатывает прошлые действия, их откат — по журналу.

## 6. Откат
Снять паузу можно только для объектов с `pause_owner=SYNC` по журналу. Откат восстанавливает статусы, но не гарантирует немедленных показов.

## 7. Нужные данные (без секретов)
| Данные | Источник | Поля |
| --- | --- | --- |
| Наличие | Merchant API products / Ads `shopping_product` | identity, availability, время чтения |
| Статусы групп | Ads `ad_group` | id, status, labels |
| Кто менял | Ads `change_event` | resource, user/client, время |
| GTIN/MPN, destinations (E10) | Merchant API products (полная карточка) | gtin, mpn, destinationStatuses — для фида, не для sync |
Ключи и токены хранятся вне репозитория.

## 8. Открыто
Частота запуска, порог свежести, число подтверждений, порог HALT, источник истины (Merchant или CS-Cart) — параметры для владельца. Синхронизация Shopping-структуры не нужна при включении OOS-товаров в allowlist пилота (см. [migration_checklist.md](migration_checklist.md)).
