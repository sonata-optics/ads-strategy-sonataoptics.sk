# SK — единая методика экономики, версия 1
Дата: 14.11.2026. Решение модератора после круга 1; требуется проверка круга 2. Это методика, не назначенные ставки или бюджет и не применённые настройки.

## Источник покупки и value
Источник бизнес-истины — оплаченный заказ CS-Cart с уникальным transaction_id и состоянием возвратов. Для e-commerce цель — одна проверенная покупка без дублей между импортом GA4 и прямой отправкой Ads. Квалифицированные лиды шоурума/B2B могут иметь отдельные цели в отдельных кампаниях; нельзя автоматически перевести все лиды аккаунта в Secondary. Проверять также campaign goals и custom goals: Secondary внутри custom goal всё равно участвует в ставках.

Каноническая выручка для анализа и предлагаемого будущего value: сумма товаров после скидок, без НДС и доставки, с вычитанием фактических полных/частичных возвратов. Ставка применяется по строке заказа, а не 23% ко всему каталогу. Базовая ставка SK — 23%; льготные ставки проверяются по SKU/операции. НДС и доставка хранятся отдельно. До миграции value фиксировать дату, старую базу, новую базу и корректировать сопоставимые целевые показатели. Сейчас передача событий не менялась.

**Уточнение модератора 15.11.2026:** во всех формулах ниже value и соответствующие пороги ROAS заданы **без НДС и без доставки D_n**, с явным различением базы до возвратов и после их корректировки; фактическая база value текущего тега Ads пока не проверена. Если тег передаёт другую сумму, сравнивать её нужно с порогом для той же базы; универсальное умножение на 1,23 недопустимо при разных ставках НДС, включённой доставке или иной обработке скидок/возвратов. Это уточнение методики, не изменение тега.

## Расчёт ожидаемого вклада
На один первоначальный заказ; ниже упрощение для полного возврата, возвращённый товар восстанавливается на складе с уценкой:
- P_n = сумма нетто-цен строк после скидок; C = себестоимость без возмещаемого НДС.
- D_n = доставка, оплаченная покупателем, без НДС.
- r = вероятность полного возврата; L = уценка/списание возврата.
- F = ожидаемые фактические комиссии, включая невозмещаемые комиссии и комиссии за возврат. Если комиссия взимается с доставки, она также входит в базу.
- S_out = исходящая логистика; S_back = оплаченная магазином обратная логистика.
- H и H_ret = обработка заказа/возврата.
- D_ret = возвращаемая покупателю доставка без НДС при возврате.

```
CM_exp = (1-r)*(P_n-C) + D_n-r*D_ret
         -F-S_out-H-r*(S_back+H_ret+L)
CPA_BE_per_initial_order = CM_exp
CPA_target_per_initial_order = CM_exp - desired_profit
V_exp_adjusted = (1-r)*P_n
BE_ROAS_adjusted = V_exp_adjusted / CM_exp
Target_ROAS_adjusted = V_exp_adjusted / (CM_exp-desired_profit)
```

При частичных возвратах, разных ставках, уценке и невосстанавливаемом COGS считать ожидание по состояниям/строкам. Исторический вклад рассчитывается по фактическим данным, не по усреднённому r.

**Исправление Claude:** загрузка возврата в Ads не устраняет экономические потери возврата. Нельзя удалять r из CM_exp лишь потому, что скорректирован рекламный value. Иначе игнорируются потеря продажи, обратная логистика, обработка и уценка. Одинаковое событие должно один раз корректировать выручку в числителе и соответствующим образом менять вклад в знаменателе: это разные величины.

Если используется исходный value до возвратов, порог для него P_n/CM_exp; если value уже скорректирован, порог V_exp_adjusted/CM_exp. Их нельзя смешивать. Так же нельзя сравнивать gross ROAS с net-порогом и объявлять кампанию прибыльной/убыточной. Сам по себе gross value не доказывает убыток.

## Проверочный пример, не данные Sonata
P_n=100, C=60, r=10%, F=2, S_out=5, H=3, S_back=4, H_ret=2, L=6, D_n=0.
CM_exp=36-2-5-3-1.2=24.8.
V_exp_adjusted=90; BE_ROAS_adjusted=90/24.8≈3.629.
Порог для value до возвратов =100/24.8≈4.032.
При 100 исходных заказах и расходе 2480 вклад после рекламы равен нулю в обоих отчётах, если каждый использует свою базу.
При CM_exp≤0 платное привлечение не окупается в этой модели; при CM_exp≤desired_profit положительный допустимый CPA отсутствует.

## CPC, CPL и единицы измерения
Max CPC = CM_exp × покупки/рекламные клики (с согласованной атрибуцией и периодом).
CR сайта = покупки/сессии — другой знаменатель. Для перевода нужен коэффициент сессии/клик; напрямую умножать CPC на CR_site нельзя.
Если полные возвраты удаляют конверсии из отчёта, CPA в Ads считается на оставшуюся покупку, а не на исходный заказ. Порог на оставшуюся покупку = CM_exp/(1-r) при этом упрощении; не сравнивать его с исходным CPA.

Max CPL = P(оплата|квалифицированный лид) × CM_exp − дополнительные затраты на обработку лида, ещё не учтённые во вкладе. Данные — CRM, без двойного учёта интернет- и офлайн-заказа.

Сегментировать по вкладу заказа и роли товара. Пороги 15/25/60 €, маржа и вероятности из отзыва Claude — сценарии, не утверждённые нормы. Не назначать tROAS или бюджет без данных Sonata. Универсальный порог 30–50 покупок и eCPC не принимаются как готовый рецепт: нужны текущие требования конкретного типа кампании.

## Проверки перед реализацией
Тестовый оплаченный заказ, разные ставки, скидка, доставка, полный/частичный возврат и дубль transaction_id; сверка CS-Cart → GA4 → Ads. После смены базы пометить разрыв ряда; не пересчитывать историю простым делением на 1.23, если набор ставок/возвратов отличается.
